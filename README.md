# Мировое время

Небольшой веб-сервис, который переводит время из одного часового пояса в другой и показывает расписание международных встреч. Сделан как учебный проект, чтобы показать, что четыре сервиса (фронт, бэк, база и веб-сервис) поднимаются вместе через docker-compose.

## Что внутри

Четыре контейнера:

| Сервис      | На чём сделан                         | Порт |
| ----------- | ------------------------------------- | ---- |
| Фронтенд    | Astro (серверный режим, Node-адаптер) | 4321 |
| Бэкенд      | Node.js, Express, `pg`                | 3000 |
| Веб-сервис  | Node.js, Express, `date-fns-tz`       | 4000 |
| База данных | PostgreSQL 16                         | 5433 |

Порт БД наружу выставлен 5433. Внутри сети Docker бэкенд ходит в базу по имени сервиса `db` и порту 5432, а к веб-сервису по имени `web-service` и порту 4000.

## За что отвечает каждый сервис

- **Фронтенд** показывает страницу: принимает ввод пользователя и выводит результат. Ничего не считает и в базу не ходит.
- **Бэкенд** работает с данными: принимает запросы от фронтенда, читает и меняет встречи в базе, проверяет входные данные. Время сам не считает, а обращается к веб-сервису.
- **Веб-сервис** считает время: переводит его между часовыми поясами и учитывает летнее время. С базой не связан и ничего не знает про встречи.
- **База данных** хранит расписание встреч.

## Как это работает

Браузер разговаривает только с фронтендом. Запросы на `/api/...` Astro пересылает бэкенду. Бэкенд читает данные из PostgreSQL, а когда нужно посчитать время, обращается к веб-сервису:

```
браузер → frontend → backend ─┬─► db
                              └─► web-service
```

**Перевод времени.** Человек вводит дату, время и два пояса. Бэкенд передаёт их веб-сервису, тот превращает время в UTC и показывает его в нужном поясе. Летнее время учитывается: например, 20 октября Лондон живёт по UTC+1, а 30 октября уже по UTC+0, и разница с Токио меняется на час.

**Расписание встреч.** Встречи лежат в таблице `meetings` в PostgreSQL (начало хранится в UTC). Бэкенд берёт их из базы и отправляет веб-сервису, чтобы получить время у организатора и в выбранном поясе. Браузер сам ничего не считает, только выводит то, что пришло.

**Добавление и изменение встреч.** Время встречи вводится в часовом поясе организатора. Перед сохранением бэкенд просит веб-сервис перевести его в UTC.

## Запуск

Нужен установленный Docker Desktop. В корне проекта рядом с `docker-compose.yml` нужно создать файл `.env` со следующими переменными:

```env
POSTGRES_USER=tz_user
POSTGRES_PASSWORD=tz_pass
POSTGRES_DB=timezone_db

DB_PORT=5433
BACKEND_PORT=3000
WEB_SERVICE_PORT=4000
FRONTEND_PORT=4321
```

Для запуска нужна одна команда:

```bash
docker compose up -d --build # сборка и запуск всех четырёх контейнеров сразу
```

Прочие команды:

```bash
docker compose up -d --build backend     # сборка и запуск backend
docker compose up -d --build web-service # сборка и запуск web-service
docker compose up -d --build frontend    # сборка и запуск frontend

docker compose stop     # остановка контейнеров
docker compose down     # остановка и удаление контейнеров
docker compose down -v  # остановка и удаление контейнеров и данных БД
```

После запуска:

- сайт: http://localhost:4321
- проверка бэкенда, базы и веб-сервиса: http://localhost:3000/api/health
- проверка веб-сервиса отдельно: http://localhost:4000/health
- в pgAdmin: хост `localhost`, порт `5433`, база `timezone_db`, логин и пароль из `.env`

## API бэкенда

- `GET /api/health` проверяет, что бэкенд жив и видит базу и веб-сервис
- `GET /api/convert?time=2026-10-20T09:00&from=Europe/London&to=Asia/Tokyo` переводит время (запрос передаётся веб-сервису)
- `GET /api/meetings?tz=Asia/Tokyo` отдаёт встречи из БД, пересчитанные на нужный пояс
- `POST /api/meetings` создаёт встречу
- `PUT /api/meetings/:id` изменяет встречу
- `DELETE /api/meetings/:id` удаляет встречу

## API веб-сервиса

- `GET /health` проверка, что сервис жив
- `GET /convert?time=2026-10-20T09:00&from=Europe/London&to=Asia/Tokyo` переводит время между поясами
- `POST /format` принимает список моментов времени (в UTC) с поясами и возвращает их в виде готовых строк. Бэкенд использует его, чтобы пересчитать сразу все встречи
